- tipikal fullstack app itu ada frontend dan backend
- untuk komunikasi keduanya
	- user melakukan action (misal search something)
	- frontend send HTTP request to backend
	- backend cari dan ambil data dari database -> bentuk datanya JSON
	- frontend menampilkan data -> convert dari JSON menjadi form human readable (user interface)
- satu buah pipeline dari llm app seringkali take so much time
	- misal, ekstrak data dari internet. cari produk paling viral di toko oren
	- prosesnya: fetch ke toko oren -> dicari datanya -> ekstrak datanya -> bisa dipake/dimasukkan db
- tapi HTTP request itu didesain untuk meng-handle proses yang selesai secepatnya
- kalau tidak selesai dengan cepat, yang terjadi di UI ada freezing. tidak boleh di-refresh, hanya menunggu. menjadikan UX-nya jelek.
- ada cara handle-nya dengan menggunakan proses queue
- jadi prosesnya yang tidak bisa selesai secepatnya itu jalan di background worker

- di product endpoint llm application, itu pake 2 cara
	- HTTP request langsung, seperti app biasa -> untuk pipeline yang bisa selesai dengan cepat
	- dengan pake worker -> untuk pipeline yang panjang proses di balik layarnya sehingga tidak bisa selesai secepatnya

- konvension -> istilah untuk sesuatu harus mengikuti aturan

- HTTP Method
	- GET -> request resource
	- POST -> create resource
	- PUT/PATCH -> PUT for update/edit resource menyeluruh; PATCH for update/edit resource parsial (beberapa field saja)
	- DELETE -> menghapus resource
- Resource itu apa? kumpulan entitas/endpoint yg diserve melalui API
	- konvension nya menggunakan plural, misal /users, /products

#### ==*Intro Project Hono*==
- starting app -> `pnpm create hono`
- ![Pastedimage20260702233538516](https://raw.githubusercontent.com/Agus-AI-PE/notes-media/main/Pastedimage20260702233538516.png)
- masuk ke folder project -> product-endpoint -> run `pnpm i`
- boilerplate code hono
	- line 1 -> karena hono runtime-agnostic perlu adapter untuk bisa jalan di nodejs
	- line 2 -> core package
	- line 4 -> init instance app
	- line 6 -> define route/endpoint dengan method GET dengan patch root dan args kedua ada controller (function yg dijalakan ketika endpoint diakses); setiap controller punya context(informasi object); setiap endpoint me-return sesuatu
	- line 10 ->  function untuk serve aplikasi hono untuk bisa dijalankan di nodejs.
	  *beda sama Express yg langsung listen(), di Hono app nya cuma expose fetch handler. jadi serve() itu adapter ke runtime tertentu*
- ![Pastedimage20260702234614951|585](https://raw.githubusercontent.com/Agus-AI-PE/notes-media/main/Pastedimage20260702234614951.png)
- untuk melakukan tes POST, PUT/PATCH, DELETE bisa pake postman(bloated) atau hoppscotch atau insomnia atau bruno, etc

- konvension dari 1 set of endpoint -> CRUD
	- GET /users
	- GET /users/:id
	- POST /users
	- PATCH /users/:id
	- DELETE /users/:id
- di hono bikin pattern-nya pake metode chaining soalnya maintainable
