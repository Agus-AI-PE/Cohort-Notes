- limitasi LLM -> pretrained data
	- karena data yg di-training ini ada cut-off knowladge -> artinya ini limited pada cut-off knowladge-nya aja tidak real-time
- ==CASE DATA DI INTERNET:==
	- nah untuk crack limitasi itu, provider LLM menyediakan juga tools call di infrastruktur bawaan masing-masing provider untuk mendapatkan real-time data di internet
		- OpenAI -> Web Search + Computer Use
		- Perplexity -> Web Search + Computer Use
		- Grok -> Live Search (Web + X)
	- Web Search -> model bisa mencari informasi terbaru di internet, membaca sumber data, hingga melakukan Deep Research sebelum memberikan jawaban
	- Computer Use -> AI bisa "melihat" layar melalui _screenshot_, lalu menggerakkan _mouse_, mengeklik, mengetik, dan menjelajahi _browser_ virtual secara mandiri untuk menyelesaikan tugas
	- cuma ini costly belum lagi ada hidden cost-nya pas di mekanisme agent loop-nya 
		- token vision -> computer use
		- context window bloat -> web search -> cenderung memasukkan raw HTML/text dari hasil pencarian ke context window, menyebabkan input token membengkak dg "sampah/iklan/etc" yang sebenarnya gak relevan
	
- ==CASE DATA DI INTERNAL (PERSONAL/PERUSAHAAN):== solusinya bisa pakai
	- RAG -> menambahkan "contekan" untuk LLM untuk bisa dimengerti
		- ada 2 prosesnya, preprocess dan retrieval
		- preprocess -> mengolah data (text, image, doc) menjadi embeddings yg dimasukkan ke dalam VectorDB
			- Vector? representasi matematika dalam memahami sebuah natural language (NL)
			- di proses ini data akan di-chunking (proses mencacah data menjadi bagian lebih kecil) kemudian diubah menjadi embaddings
		- retrieval -> memahami satu buah knowladge di luar yg diketahui LLM
		- ![Pastedimage20260802012616733|523](https://raw.githubusercontent.com/Agus-AI-PE/notes-media/main/Pastedimage20260802012616733.png)
		- kalau LLM biasa itu prosesnya: `UserInput -> LLM`
		- + flexible (knowladge-nya bisa di-swap kapan aja tanpa perlu fine-tuning)
		- + ekonomis
		- - latency lebih lama
	- Fine-Tuning -> re-train data -> bisa di local bisa di sewa claster GPU cloud (e.g. Unsloth, runpod)
		- + less latency
		- + build-in knowladge
		- kebutuhan khusus domain expert (field tertentu kaya healthcare)
		- - mahal banget, enterprise lah
- untuk membuat LLM punya knowladge beyond the pre-trained data
